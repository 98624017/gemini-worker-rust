# 04 — FAST 与 RELAX 多参考图保持顺序并同步生成

## What to build

调用方可在 mj_fast_imagine 或 mj_relax_imagine 中提交多张参考图 URL。代理按约定顺序准备全部图片、转换为 Base64，一次创建任务并同步返回 OpenAI 图片结果；任意一张图片失败都使整次请求明确失败。

最终交付两个模式下完整的中文文生图、单参考图和多参考图体验。六张是代理的输入数量限制，不作为上游已验证支持六张的承诺。

## Acceptance criteria

- [ ] 两个模型都支持 image、images、reference_images 合并后的 1 至 6 张参考图；超过六张、任一字段或成员非法时在创建任务前返回清晰 400。省略或空数组保持文生图，不引入 Blend、Upscale 或额外公开任务接口。
- [ ] 按既有别名归一化顺序生成 base64Array，保留每个数组项及重复项；允许重复 URL 去重下载，但并发完成顺序不得改变最终排列，也不得去除重复参考图。
- [ ] 每张图独立满足既有单图合同：最长边不超过 2048，不放大小图；JPEG/WebP 合规尺寸时原字节保留，PNG 转 JPEG quality=98、4:4:4、透明白底，超限等比缩小且 MIME 与字节一致。
- [ ] 所有图片准备成功后才提交一次任务。任一图片下载、尺寸处理、解码、编码或预算失败，整次请求明确失败，诊断能定位失败图片及阶段；禁止提交部分参考图或降级文生图。
- [ ] FAST 和 RELAX 分别使用正确提交路径、mode 及唯一 --fast/--relax；多图不改变中文正文、版本参数和已有同步轮询、错误及 OpenAI 结果合同。不把参考图 URL 拼入 prompt，也不先上传 Uguu。
- [ ] 复用有界下载和图片工作并发及 Blob Runtime 内存/临时存储预算，避免每张大图及编码载荷被多份同时保留；全部准备、提交和查询共用请求起始的绝对截止时间，失败、取消和超时释放请求级资源并停止本请求后续操作，不破坏共享服务生命周期。
- [ ] 缓存命中与禁用不会改变任何参考图的格式合同或数组顺序；每个 base64Array 项都被日志脱敏，诊断保留任务、阶段和实际模式。泛化的“Prompt图片未通过审核”仍不作为新增长期违规缓存分类。
- [ ] 通过下游 HTTP 入口、本地图片源和模拟 Magic 验证两个模型下的单图和双图、重复 URL、延迟乱序、别名合并、六张边界、七张拒绝、单项失败零提交、缓存与大载荷清理；不依赖私有函数结构，重跑直接受影响的文生图及其他渠道兼容验证。
- [ ] 调用文档覆盖两个模型的中文文生图、单图及双图示例、只返回 url、六张本层上限、预处理规则、默认返回全部候选及主图回退、600 秒默认预算和兼容占位 usage，不宣称全面兼容 OpenAI 所有生成参数。
- [ ] 经新增 OpenAI 代理链路验收 FAST 和 RELAX 各自的中文文生图、中文单参考图、中文双参考图；前序 tickets 已完成且链路未变的实测可复用，不机械重复计费调用。双图使用 https://img.cdn1.vip/i/69a3fd7a9d39a_1772354938.webp 和 https://img.cdn1.vip/i/69e9c4bc4e0db_1776927932.webp，核对可访问性、处理后 MIME/尺寸、任务终态、实际模式、任务 ID、耗时及返回图片下载。
- [ ] 双参考图必须验证实际发送的是两个 Base64 Data URI；既有双 URL 成功和原生单图成功均不能替代。若上游拒绝或无法完成实测，如实记录任务及错误和限制，不声称已跑通，不擅自改用 Blend、图床 URL 或再次创建任务掩盖失败。
