# 03 — 单参考图 URL 经预处理和 Base64 提交后同步生成

## What to build

调用方在 mj_fast_imagine 请求中增加一张 HTTP(S) 参考图 URL，即可经同一个 OpenAI 接口完成参考图生成。代理下载原图，按尺寸和格式合同处理，转换为 Base64 Data URI，再创建 Magic 任务并同步返回结果。调用方无需编码图片或先上传图床。

以 FAST 完成独立验收，图片处理规则与模式无关；RELAX ticket 完成后沿用同一参考图行为，双模型组合在多参考图 ticket 中统一验收。

## Acceptance criteria

- [ ] image、images、reference_images 沿用既有别名和合并顺序；本 ticket 打通合并后一张 URL 的请求。合并后多张在多图 ticket 完成前明确拒绝，不能只取首张。省略或空数组仍为文生图。
- [ ] 图片字段为 HTTP(S) URL 字符串数组；null、标量、非字符串成员、非法 URL、Data URI 和原始 Base64 在创建任务前明确返回 400，不新增下游私有 base64Array 输入能力。
- [ ] 代理使用既有图片客户端及网络目标约束下载参考图，每张沿用 20MiB 限制和现有下载超时；不向图片源发送上游 API key，不仅凭 URL 后缀判断格式。
- [ ] JPEG、PNG、WebP 按实际可解码字节识别；不支持的格式和损坏图片明确返回 400，网络下载失败沿用 502。失败不创建任务，不丢图执行文生图。
- [ ] 最长边超过 2048 才等比缩小，不放大、不裁切、不拉伸；任意一边至少为 1，最长边不超过 2048。2047、2048、2049 边界、横竖图和极端宽高比满足相同合同。
- [ ] JPEG/WebP 最长边不超过 2048 时保留原始字节和格式；超限缩小后仍保持原格式。JPEG 重编码采用质量 98、YCbCr 4:4:4；WebP 使用现有无损编码并保留透明通道。
- [ ] PNG 无论是否缩小都转为 JPEG，质量 98、4:4:4，透明区域合成白底。“443”按规格草案解释为 4:4:4。强制尺寸及格式合同不受“编码更大返回原图”和通用响应压缩开关影响。
- [ ] Magic 接收的 base64Array 恰有一项，内容为最终实际 MIME 对应的完整 Data URI；可解码为满足上述合同的图片，不含源图 URL。上游只带 mode、规范化 prompt、base64Array，不转发下游包装字段。
- [ ] 缓存命中、未命中、禁用缓存和已有通用 PNG→WebP 缓存变体均不能改变 MJ 图片处理合同；取得原始载荷，或隔离处理变体，必要时绕过不兼容变体，不污染其他渠道的共享下载缓存。
- [ ] 图片解码和变换在阻塞任务边界执行；下载、处理和编码复用既有有界资源及 Blob Runtime 预算，避免保留多份完整图片、Base64 和 JSON。处理、提交和轮询共用请求起始的绝对截止时间；成功、失败和取消均释放请求级临时资源。
- [ ] admin 对实际上游请求的 base64Array 逐项脱敏，仅保留 MIME、大小等摘要；不记录完整 Data URI、Base64 或 key，仍能定位准备、提交和查询阶段。图片下载或暂时审核错误不扩展长期违规缓存分类。
- [ ] 从下游 HTTP 入口使用本地图片源和模拟 Magic 捕获最终 Data URI，检查字节、格式、尺寸、JPEG 采样及透明白底；覆盖错误和缓存路径，并确认其他渠道处理及文生图不回归。必要时增加窄输出格式断言，不增加产品测试专用接口。
- [ ] 补充单参考图调用说明；经新增代理链路完成 FAST 中文 v8.1 单图实测，记录输入处理后 MIME/尺寸、任务终态、实际模式、任务 ID、耗时和返回 URL 可下载性。若无法实测，明确记录未验证。
